RSS2

Multilingual RSS news aggregator

RSS2 collects news from thousands of international sources, detects their language, translates them into Spanish, extracts the entities they mention and links them by semantic similarity. Everything is read from a single web app on port 8888.

From thousands of scattered sources to a connected, searchable and narrated news archive.

  • Status Active development
  • License MIT (code)
  • Backend Go
  • Data PostgreSQL 16 + pgvector
  • Deployment Docker Compose

No public demo: the figures on this page come from an audited lab instance.

What it is

Ingestion, translation and analysis in one system

RSS2 is a self-hosted aggregator that turns a continuous flow of feeds into a queryable news database. A Go ingestor downloads the sources every eight minutes; a chain of workers detects the language, translates into Spanish with NLLB, extracts entities with spaCy, computes embeddings and groups the news that tell the same story. The Go API and the React SPA are published together behind nginx on a single port.

Pipeline

From feed to related story

RSS/Atom feeds
   │  ingestor (Go, every 8 min)
   ▼
PostgreSQL 16 + pgvector
   │
   ├─ langdetect ──► translation-scheduler ──► translator (NLLB-200)
   ├─ ner (spaCy) ──► entities + co-occurrences
   ├─ embeddings ──► related + event-clustering
   ├─ topics ──► categories and country
   ├─ wiki ──► entity context
   └─ scraper / discovery ──► summaries and new sources
   ▼
Go API :8080 ──► nginx :8888 ──► React SPA

Redis caches responses and rate-limits requests. Docker Compose adds optional GPU profiles for the translator and monitoring with Prometheus, Grafana and cAdvisor.

  • Ingestion

    Thousands of sources

    A Go ingestor walks the RSS/Atom feeds every eight minutes and drops duplicates before inserting.

  • Language

    Automatic detection

    langdetect tags the language of every news item and feeds the translation queue.

  • Translation

    NLLB-200 on CPU or GPU

    CTranslate2 serves NLLB-200 distilled 600M and translates content into Spanish.

  • Entities

    NER with spaCy

    es_core_news_lg extracts people, organisations and places; co-occurrences are precomputed for the graph.

  • Search

    Semantic search with pgvector

    Multilingual embeddings allow search by meaning and combine date, topic, country and category filters.

  • Trends

    Grouped stories

    Similarity clustering separates one story from the five sources telling it and rates its importance.

  • Context

    Wikipedia

    Wikipedia summaries and images linked to the entities that appear in the news.

  • Voice

    TTS bulletins

    Editable scripts, two editorial approvals and WAV audio with Chatterbox, MeloTTS or OpenVoice.

  • Operations

    A single port

    nginx publishes the SPA and the API on :8888; Redis caches and rate-limits; Compose adds GPU and monitoring.

Voice bulletin

A spoken newsreel with editorial control

The voice subsystem is optional and turns the news into a bulletin: you search, choose, fix the text and generate the audio. Everything happens in the web app, and nothing is published automatically.

  • Search and choose by keyword or trend, with a time window, relevance ordering and one item per story.
  • Review the full script of every item, with characters and estimated duration.
  • Process: the edits are saved, the bulletin is created and the narration is queued asynchronously.

Two approval gates

  • The editor approves the content and generates the narrations.
  • An administrator approves the assembled audio; there is no publication endpoint.

Voices: Chatterbox by default, the Spanish base voice, 256 model speakers, OpenVoice or a clone registered from a sample (administrators only). Speed from 0.7x to 1.5x. On CPU narration runs at ~1.5x real time.

Status

Audit of a lab instance

The latest published audit (12 October 2026) measured the full system with every service healthy:

  • 1,284,617 news items and 28,704 registered sources.
  • 195 countries, 15 categories and 194,324 translations.
  • 375,120 entity co-occurrences precomputed for the graph.
  • /api/stats in ~50 ms and the entity graph in ~200 ms.
  • CI green on the latest master run: Go tests with vet and gofmt, React tests and build, and the init-db schema from scratch with drift checks.

Known limits

  • The MIT licence covers the code: the NLLB-200 weights are CC-BY-NC 4.0 and restrict commercial use.
  • The backend takes ~5 minutes to start because of indexes and statistics on large tables.
  • TTS on CPU runs at ~1.5x real time; the queue is asynchronous.
  • No public demo and no tagged releases: the figures come from a lab instance.
  • Part of the corpus has corrupt dates and few recent items: the 24 h window may return nothing.

Get started

Run RSS2 locally

You need Docker and Docker Compose, 8 GB of RAM recommended and about 20 GB of disk. The first start takes around five minutes.

git clone https://github.com/Dinamicas-Electronicas/rss2.git
cd rss2
cp .env.example .env      # POSTGRES_PASSWORD, REDIS_PASSWORD, SECRET_KEY
docker compose up -d --build

Open http://localhost:8888. The voice bulletin is optional: it needs the model weights via make tts-models.
