RSS2

Agregador multilingüe de noticias RSS

RSS2 recoge noticias de miles de fuentes internacionales, detecta su idioma, las traduce al español, extrae las entidades que mencionan y las relaciona por similitud semántica. Todo se consulta desde una única web en el puerto 8888.

De miles de fuentes dispersas a una hemeroteca conectada, buscable y narrada.

  • Estado Desarrollo activo
  • Licencia MIT (código)
  • Backend Go
  • Datos PostgreSQL 16 + pgvector
  • Despliegue Docker Compose
Ver en GitHub Cómo funciona

Qué es

Ingesta, traducción y análisis en un solo sistema

RSS2 es un agregador autoalojado que convierte un flujo continuo de feeds en una base de noticias consultable. Un ingestor en Go descarga las fuentes cada ocho minutos; una cadena de workers detecta el idioma, traduce al español con NLLB, extrae entidades con spaCy, calcula embeddings y agrupa las noticias que cuentan la misma historia. La API Go y la SPA de React se publican juntas detrás de nginx en un único puerto.

Pipeline

Del feed a la noticia relacionada

feeds RSS/Atom
   │  ingestor (Go, cada 8 min)
   ▼
PostgreSQL 16 + pgvector
   │
   ├─ langdetect ──► translation-scheduler ──► translator (NLLB-200)
   ├─ ner (spaCy) ──► entidades + co-ocurrencias
   ├─ embeddings ──► related + event-clustering
   ├─ topics ──► categorías y país
   ├─ wiki ──► contexto de entidades
   └─ scraper / discovery ──► resúmenes y nuevas fuentes
   ▼
API Go :8080 ──► nginx :8888 ──► SPA React

Redis cachea respuestas y limita peticiones. Docker Compose añade perfiles opcionales de GPU para el traductor y de monitorización con Prometheus, Grafana y cAdvisor.

  • Ingesta

    Miles de fuentes

    Un ingestor en Go recorre cada ocho minutos los feeds RSS/Atom y descarta duplicados antes de insertar.

  • Idioma

    Detección automática

    langdetect marca el idioma de cada noticia y alimenta la cola de traducción.

  • Traducción

    NLLB-200 en CPU o GPU

    CTranslate2 sirve NLLB-200 distilled 600M y traduce el contenido al español.

  • Entidades

    NER con spaCy

    es_core_news_lg extrae personas, organizaciones y lugares; las co-ocurrencias se precalculan para el grafo.

  • Búsqueda

    Semántica con pgvector

    Embeddings multilingües permiten buscar por significado y combinar filtros de fecha, tema, país y categoría.

  • Tendencias

    Historias agrupadas

    El clustering por similitud separa una historia de las cinco fuentes que la cuentan y marca su importancia.

  • Contexto

    Wikipedia

    Resúmenes e imágenes de Wikipedia enlazados a las entidades que aparecen en las noticias.

  • Voz

    Noticiario TTS

    Guiones editables, dos aprobaciones editoriales y audio WAV con Chatterbox, MeloTTS u OpenVoice.

  • Operación

    Un solo puerto

    nginx publica la SPA y la API en :8888; Redis cachea y limita peticiones; Compose añade GPU y monitorización.

Noticiario por voz

Un informativo hablado, con control editorial

El subsistema de voz es opcional y convierte las noticias en un informativo: se buscan, se eligen, se corrige el texto y se genera el audio. Todo ocurre en la web, sin publicar nada automáticamente.

  • Buscar y elegir por palabra clave o tendencia, con ventana temporal, orden por relevancia y una noticia por historia.
  • Revisar el guion completo de cada noticia, con caracteres y duración estimada.
  • Procesar: se guarda lo corregido, se crea el noticiario y se encola la locución de forma asíncrona.

Dos puertas de aprobación

  • El editor aprueba el contenido y genera las narraciones.
  • Un administrador aprueba el audio montado; no existe ningún endpoint de publicación.

Voces: Chatterbox por defecto, la base en español, 256 hablantes del modelo, OpenVoice o un clon registrado con una muestra (solo administradores). Velocidad de 0,7x a 1,5x. En CPU la locución va a ~1,5x el tiempo real.

Estado

Auditoría de una instancia de laboratorio

La última auditoría publicada (12 de octubre de 2026) midió el sistema completo con todos los servicios healthy:

  • 1.284.617 noticias y 28.704 fuentes registradas.
  • 195 países, 15 categorías y 194.324 traducciones.
  • 375.120 co-ocurrencias de entidades precalculadas para el grafo.
  • /api/stats en ~50 ms y el grafo de entidades en ~200 ms.
  • CI en verde en la última ejecución de master: tests de Go con vet y gofmt, tests y build de React, y esquema init-db desde cero con control de deriva.

Límites conocidos

  • La licencia MIT cubre el código: los pesos de NLLB-200 son CC-BY-NC 4.0 y restringen el uso comercial.
  • El backend tarda ~5 minutos en arrancar por los índices y estadísticas sobre tablas grandes.
  • El TTS en CPU va a ~1,5x el tiempo real; la cola es asíncrona.
  • Sin demo pública ni releases etiquetadas: las cifras son de una instancia de laboratorio.
  • Parte de las fechas del corpus está corrupta y hay pocas noticias recientes: la ventana de 24 h puede devolver vacío.

Empezar

Levantar RSS2 en local

Necesitas Docker y Docker Compose, 8 GB de RAM recomendados y unos 20 GB de disco. El primer arranque tarda unos cinco minutos.

git clone https://github.com/Dinamicas-Electronicas/rss2.git
cd rss2
cp .env.example .env      # POSTGRES_PASSWORD, REDIS_PASSWORD, SECRET_KEY
docker compose up -d --build

Abre http://localhost:8888. El noticiario por voz es opcional: requiere descargar los pesos con make tts-models.
